# 开发与审查接力

一个可信本地任务由 Codex 实现、项目命令检查、Claude Code 独立审查；检查失败或发现需要修复的问题时，反馈自动进入下一轮实现。默认最多三轮，包含初次执行。代码指纹相同、全部检查成功且审查没有阻塞意见时才结束。

这是普通 `command` Agent 执行的一项有限工作，中台继续负责排队、进程、卡片和停止。它没有自己的定时器、事件队列或后台服务。外部事件只负责唤醒，不提供命令、路径、权限或任务目标。

阻塞卡片会在可见正文中说明目标、当前阶段、已保存的工作、影响、需要本人做什么、续接范围和证据，不把这些内容只放在通道看不到的 `about` 中。新开发使用原仓库功能分支时，见相邻的 `personal-team` 配方。

审查内部统一使用 `{title, text}`。兼容已实际出现的旧原生审查字符串数组时，保留每条意见的完整文字并生成标题，非空意见仍然要求返工；空白字符串、缺字段对象等无效结果仍阻塞，不能转换成通过。

## 准备

1. 从本人可信的项目创建一个干净、独立的代码副本，保留正在使用的工作目录。该副本仅用于这一项任务，不与其他人或 agent 同时修改。
2. 将 `TASK.example.md` 复制到代码目录之外的 `task.md`，填写具体目标、计划依据和验收条件。这个文件是本人维护的可信任务，不使用外部评论或网页正文直接覆盖它。
3. 将 `team.example.json` 复制到本机私有目录，替换绝对路径。`stateDirectory` 和 `taskFile` 必须在代码目录之外；每项新任务使用新的代码副本和状态目录。
4. 将 `checks` 替换为该任务实际需要的检查，不仅是示例命令。检查使用独立参数数组，不经过 shell；Windows 的 npm `.cmd` 包装由项目现有命令处理器解析。检查命令不得改写业务代码。
5. 在相同后台运行环境验证 CLI 接入：

   ```powershell
   node C:/path/agent-autoloop/examples/recipes/code-review-loop/run.ts C:/private/team.json --check
   ```

   此命令不调用模型或执行开发。桌面应用已登录不代表当前 PATH 的 CLI 可用，额度也须在实际执行时核实。使用已有启动包装时，可配置绝对路径 `coderProgram`、`reviewerProgram`；不要把密钥写入配置。

需要先审查已经实现的分支时，设置 `start` 为 `review`，并以完整提交号设置可信的 `reviewBase`。流程先运行检查，再审查相对此提交的全部改动；有意见才进入实现。未填写 `reviewBase` 时，审查基线为任务开始的 HEAD。任务基线的 HEAD 在执行期间不得改变。

审查使用 CLI 的 `--json-schema` 和 `structured_output`，以免将自然语言总结当成无问题结论，见 [Claude Code 官方非交互文档](https://code.claude.com/docs/en/headless#get-structured-output)。

## 接入中台

将本目录 `rules.json` 的 Agent 和规则合入本人现有配置，替换接单电脑、代码目录、引擎和任务配置路径。使用现有来源与通知通道，按需给规则添加 `channels`。每份任务配置只启用一个执行者；不要在中台执行期间手动运行同一任务。

```powershell
node C:/path/agent-autoloop/bin/agent-autoloop.ts check C:/private/rules.json
node C:/path/agent-autoloop/bin/agent-autoloop.ts run 开发审查接力
```

也可从本人配置的来源发 `code.request` 事件。内容不会替换可信的 `task.md`。完成后通过既有通道或 `status` 查看结果，产物和详细证据留在隔离代码目录与状态目录。

权限：Codex 为 `edit`，Claude 为 `read`，分别使用现有专用适配器的权限映射。通用 `command` 本身不提供沙箱，Claude 的计划模式也不是操作系统隔离。CLI 和检查命令只适用于本人信任的本地项目。模型与推理设置沿用各 CLI 当前配置。

## 中断、额度与决定

实现、检查、审查的阶段分别保存。审查工具无法使用时会交回 `ask`，该轮退出；恢复连接或额度后回答“已处理，继续”，从审查阶段继续。等待期间没有模型进程。不会用定时模型请求探测额度。

实现阶段需要本人决定时，Codex 可交回标准 `agent-autoloop ask`，回答进入下一轮资料并续接会话。“停止这个任务”会保存终止状态。命令中途退出时，后续执行使用已有阶段与日志中的会话；整机断电的文件持久性尚未验证。

`state.json` 记录阶段、轮次、任务摘要和代码版本；各轮的检查与审查 JSON 记录证据，子目录保存两个 CLI 的输出。任务目标、检查策略或目录变化时不能沿用旧任务状态。代码检查期间或审查之后的代码变化会阻止验收。

此版本产出本地代码和审查证据。提交、推送、合并、发布与设备验收仍按具体任务的项目约定和本人授权处理。通用命令目前不将内部两种 CLI 的用量汇总到中台统计。

## 当前验证范围

自动测试使用真实子进程、Git 隔离仓库和项目检查命令，两个模型 CLI 使用符合其输出协议的替身，验证返工、工具中断、过期审查、次数上限和决定处理。它不证明真实模型的代码质量、账号登录或设备验收能力；真实接入需要在本机额外跑通。
